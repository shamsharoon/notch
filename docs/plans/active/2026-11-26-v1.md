# v1: personal fork with per-app Mixer

## Purpose
Build v1 from `SPEC.md`: the fork runs as its own app with Sparkle off, and adds a per-app volume Mixer as a notch tab and in the menu bar panel. "Done" means every feature in `features.json` passes.

## Findings
- Xcode 27.2 is now installed at `/Applications/Xcode.app`, but `xcode-select` still points at Command Line Tools. Build with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`.
- Baseline: unchanged upstream (`1cbfb69`) builds with `xcodebuild -scheme boringNotch -configuration Debug -derivedDataPath build/DerivedData CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO build` → BUILD SUCCEEDED. `build/` is gitignored.
- The project uses file-system synchronized groups, so new files in `boringNotch/Mixer/` join the target with no `project.pbxproj` edit.
- Bundle IDs: app `theboringteam.boringnotch` (pbxproj lines ~1253, ~1307), helper `theboringteam.boringnotch.BoringNotchXPCHelper` (pbxproj ~1053, ~1078). The helper name is also hard-coded in `BoringNotchXPCHelper/BoringNotchXPCHelperProtocol.swift:28` and `boringNotch/XPCHelperClient/XPCHelperClient.swift:8`. Product name is "Boring Notch".
- Sparkle: `SPUStandardUpdaterController(startingUpdater: true)` in `boringNotch/boringNotchApp.swift:24`; `SUFeedURL` in `boringNotch/Info.plist`; update UI in the menu (`CheckForUpdatesView`) and in Settings > About (`SettingsView.swift` ~837–906).
- Deployment target is macOS 14.0 everywhere. `CATapDescription` needs 14.2.
- Tabs only show when the shelf has items or `alwaysShowTabs`, and only when `Defaults[.boringShelf]` is on (`boringNotch/components/Notch/BoringHeader.swift:18`). A Mixer tab must always be reachable, so this condition changes.
- Mixer source: `~/Code/mixer/Sources/Mixer/` at `cdc3703`, 697 lines. `MixerModel` stores volumes and mutes as two separate `UserDefaults` keys.

## Data shape
- `MixerSetting { volume: Double (0–1), muted: Bool }`, stored as one `Defaults` key `[bundleID: MixerSetting]`. An entry at volume 1 and not muted is removed. One map, not two keys that must stay in sync.
- One `MixerModel.shared` (`@MainActor ObservableObject`) owns apps, settings and taps. The notch tab and the menu bar panel both observe it, so they cannot disagree.
- An app gets a tap only when its setting is below 1 or muted.

## Decision Log

- 2026-11-26: Identity is product name `Notch`, app `local.notch`, helper `local.notch.XPCHelper`. - 2026-11-26: Sparkle off by hiding, not unlinking. Removed the feed and key from `Info.plist`, start the updater with `startingUpdater: false`, and removed the two update views from Settings > About and the menu. `SoftwareUpdater.swift` stays as unused upstream code so upstream merges stay clean.
- 2026-11-26: `boringNotch/Mixer/` joins the target as its own `PBXFileSystemSynchronizedRootGroup` (3 pbxproj lines, same as `private/`), instead of 4 pbxproj entries per file. Later Mixer files need no pbxproj edit.
- 2026-11-26: One `MixerSetting.needsTap` rule decides both "keep the saved entry" and "keep a tap", so storage and taps cannot disagree. `errorMessage` is recomputed on every tap pass, so it clears once nothing fails. The permission message lives in the model from step 3; step 6 only adds the plist key and entitlement.
- 2026-11-26: `MixerModel.shared.start()` runs at the end of `applicationDidFinishLaunching`; `stop()` runs in `applicationWillTerminate` and removes every tap.

## Surprises
- The Findings said the project uses file-system synchronized groups for `boringNotch/`. It does not: only `private/` and `BoringNotchXPCHelper/` are synchronized. New Mixer files failed with "cannot find 'MixerModel' in scope" until the Mixer folder got its own synchronized group.
